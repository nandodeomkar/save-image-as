# Plan 01-01: Extension Build Pipeline, Manifest V3 Config & Base Type Definitions

## Objective
Establish the foundational project structure for a Chromium Manifest V3 browser extension using Vite, TypeScript, and Vitest. Configure multi-entry build targets for the background service worker, offscreen document, content script, and popup UI. Define core shared TypeScript types and create crisp vector/raster extension icons.

## Requirements Addressed
- **ARCH-01**: Extension is packaged under Chrome Extensions Manifest V3 specification with appropriate permissions (`contextMenus`, `downloads`, `storage`, `offscreen`, `activeTab`, `scripting`, `<all_urls>`).
- **ARCH-04**: Modern build pipeline (Vite + TypeScript + Vitest) packages background, content, offscreen, and popup scripts into optimized bundles.

## Tasks

### 1. Initialize `package.json` with Dependencies & Scripts
- Setup root `package.json` with ES module support (`"type": "module"`).
- Add runtime dependencies for client-side conversions:
  - `jspdf` (for PDF wrapper generation)
  - `omggif` (for GIF binary encoding)
- Add dev dependencies:
  - `typescript`, `@types/chrome`, `@types/node`
  - `vite`, `@vitejs/plugin-basic-ssl` (or custom rollup config for multi-entry MV3)
  - `vitest` (for lightning-fast unit testing)
- Configure scripts:
  - `npm run build`: Bundles all extension components into `dist/`
  - `npm run dev`: Runs Vite in watch mode for extension development
  - `npm run test`: Runs unit tests via Vitest
  - `npm run typecheck`: Runs `tsc --noEmit` for full type verification

### 2. Configure TypeScript (`tsconfig.json`)
- Configure modern TypeScript settings targeting ES2022.
- Include `"DOM"`, `"DOM.Iterable"`, `"WebWorker"`, and `"ES2022"` lib definitions.
- Enable `strict: true`, `skipLibCheck: true`, `moduleResolution: "bundler"`, and alias paths `@/*` -> `src/*`.

### 3. Configure Multi-Entry Vite Build (`vite.config.ts`)
- Setup Rollup multi-input bundling for:
  - `background`: `src/background/service-worker.ts` -> `dist/background/service-worker.js`
  - `content`: `src/content/inspector.ts` -> `dist/content/inspector.js`
  - `offscreen`: `src/offscreen/offscreen.html` (including `offscreen.ts`) -> `dist/offscreen.html`
  - `popup`: `src/popup/popup.html` (including `popup.ts`) -> `dist/popup.html`
- Configure asset copying to ensure `manifest.json` and icons are copied directly to `dist/`.
- Ensure output naming is deterministic (no random hash chunks in entry filenames that would break manifest paths).

### 4. Create Chrome Manifest V3 Definition (`manifest.json`)
- Manifest version `3`.
- Extension metadata: `name: "Save Image As - Fast Image Converter"`, `version: "1.0.0"`, `description: "Instantly convert and download any web image in JPG, PNG, WebP, AVIF, BMP, GIF, ICO, PDF, SVG with a single click."`
- Permissions:
  - `contextMenus` (for right-click format sub-menu)
  - `downloads` (for downloading converted images directly)
  - `storage` (for sync preferences)
  - `offscreen` (for headless canvas execution environment)
  - `activeTab` (for element inspection)
  - `scripting` (for dynamic content script execution if needed)
- Host permissions:
  - `<all_urls>` (for fetching image blobs from external CDNs without CORS restrictions)
- Background service worker:
  - `service_worker: "background/service-worker.js"`, `type: "module"`
- Action:
  - `default_popup: "popup.html"`, `default_icon: { "16": "icons/icon-16.png", "32": "icons/icon-32.png", "48": "icons/icon-48.png", "128": "icons/icon-128.png" }`
- Content scripts:
  - Matches: `<all_urls>`
  - JS: `["content/inspector.js"]`
  - Run at: `document_idle`
- Icons: 16x16, 32x32, 48x48, 128x128.

### 5. Generate Extension Icons (`src/assets/icons/` & `public/icons/`)
- Design a clean, modern extension icon in SVG format featuring an image canvas / download arrow motif with rich indigo & cyan gradient styling.
- Render crisp PNG versions at 16x16, 32x32, 48x48, and 128x128 pixels.

### 6. Create Base Shared Types (`src/utils/types.ts`)
- Define all supported image formats:
  ```typescript
  export type ImageFormat = 'png' | 'jpeg' | 'webp' | 'avif' | 'bmp' | 'gif' | 'ico' | 'pdf' | 'svg';
  ```
- Define message protocol schemas:
  ```typescript
  export type MessageType =
    | 'OFFSCREEN_PING'
    | 'OFFSCREEN_PONG'
    | 'CONVERT_IMAGE_REQUEST'
    | 'CONVERT_IMAGE_RESPONSE'
    | 'FETCH_IMAGE_REQUEST'
    | 'INSPECT_ELEMENT_REQUEST'
    | 'INSPECT_ELEMENT_RESPONSE'
    | 'DOWNLOAD_IMAGE_REQUEST';
  ```
- Define user settings and storage interfaces:
  ```typescript
  export interface ExtensionSettings {
    enabledFormats: ImageFormat[];
    defaultFormat: ImageFormat;
    jpegQuality: number; // 0.1 to 1.0
    webpQuality: number; // 0.1 to 1.0
    avifQuality: number; // 0.1 to 1.0
    backgroundColor: string; // hex color for alpha flattening (e.g. #FFFFFF)
    filenameTemplate: string; // e.g. "[name]-[page-title]-[timestamp].[ext]"
    shortcutModifier: 'alt' | 'ctrl' | 'shift' | 'none';
  }
  ```
- Define conversion request & response payloads:
  ```typescript
  export interface ConvertImageRequest {
    type: 'CONVERT_IMAGE_REQUEST';
    id: string;
    source: {
      type: 'url' | 'data-url' | 'blob' | 'svg-string';
      data: string;
    };
    targetFormat: ImageFormat;
    quality?: number;
    backgroundColor?: string;
    originalFilename?: string;
  }

  export interface ConvertImageResponse {
    type: 'CONVERT_IMAGE_RESPONSE';
    id: string;
    success: boolean;
    dataUrl?: string;
    mimeType?: string;
    byteLength?: number;
    error?: string;
  }
  ```

### 7. Configure Vitest Test Framework (`tests/setup.ts`, `vitest.config.ts`)
- Set up Vitest test environment with mock helpers for Chrome runtime and storage APIs.
