# Plan 06-01: Test Fixtures Web Page & E2E Integration Test Suite

## Objective
Build a comprehensive standalone HTML fixture page containing all realistic web image structures, and implement an end-to-end integration test suite verifying the complete pipeline from DOM inspection through format conversion, alpha rendering, filename templating, and download dispatch.

## Requirements Addressed
Validates all requirements across ARCH, CONV, DOM, MENU, FILE, and UI layers.

## Tasks
1. Create `tests/fixtures/test-page.html`:
   - Standard images (JPEG, PNG with transparency, WebP, AVIF, GIF, BMP, ICO).
   - Responsive `<img>` with `srcset` (1x, 2x, 3x pixel densities and 320w, 640w, 1200w width descriptors).
   - `<picture>` tags with multiple `<source>` elements (WebP/AVIF fallback) and media queries.
   - CSS `background-image` elements (inline styles, stylesheets, nested overlay containers, pseudo elements).
   - Dynamic HTML5 `<canvas>` elements rendering shapes and charts.
   - Inline `<svg>` icons with defs/gradients, masks, and CSS stylesheets.
   - External `.svg` files.
   - Base64 data URIs and Blob URLs.
   - Deeply nested structures with overlay elements.
2. Create `tests/e2e-integration.test.ts`:
   - Load and parse `test-page.html` in JSDOM.
   - Test DOM element inspection and candidate resolution for each fixture element.
   - Test full pipeline conversion for all 9 target formats (PNG, JPG, WebP, AVIF, BMP, GIF, ICO, PDF, SVG).
   - Test alpha background fill color behavior on transparent PNGs converting to JPEG/BMP.
   - Test tokenized filename engine (`[name]`, `[ext]`, `[page-title]`, `[domain]`, `[date]`, `[timestamp]`, `[dimensions]`).
   - Test download manager execution and verification of Chrome API calls.

## Verification
- All Vitest integration tests execute cleanly and pass 100%.
